# MERGE.md — история слияния и устройство MARK.lsp

**Статус:** единая сборка `1.0`; MarkZ `48.48/36.7`, MarkV `7.0/33.19`,
ядро `1.0`.

## 1. Зачем один файл

Раньше требовалось загружать `MARKCORE.lsp`, `MARKZ.lsp`, `MarkV.lsp` в
правильном порядке. Теперь — один `MARK.lsp`:

- одно `(load ...)`;
- одна команда полного цикла `МАРКАВСЕ`;
- один `U` на весь цикл;
- нет внешних баз и поиска исходников;
- меньше команд и мёртвого кода.

Исходники не удалены: они в `backup/`, сборщик читает их и применяет
производственные патчи.

## 2. Состав

```text
MARK.lsp = HEADER + REGISTRY + MARKCORE + MARKZ + MarkV + TAIL
```

- `HEADER` — шапка сборки.
- `REGISTRY` — реестр замечаний `mc:remark*`.
- `MARKCORE` — ядро `mc:*`.
- `MARKZ` — заполнения.
- `MarkV` — каркас.
- `TAIL` — цикл `МАРКАВСЕ`, обёртки команд, help-баннер.

Сборщик `tools/build_single.py`:

1. вырезает загрузчики ядра и финальные баннеры модулей;
2. переименовывает `c:МАРКАВ` в `mk:a-all` и оставляет тонкую обёртку;
3. добавляет ключевое слово источника в `mark:a-all`;
4. добавляет цикл `МАРКАВСЕ`/`MARKALL`;
5. применяет производственные патчи (ниже);
6. вырезает разработческие команды и мёртвые функции;
7. проверяет CP1251/CRLF, отсутствие BOM/U+FFFD, `fboundp`, внешних загрузок;
8. пишет `MARK.lsp`.

`--check` сравнивает результат с файлом на диске.

## 3. Производственные патчи

Помимо склейки, сборщик меняет поведение:

- **Реестр замечаний** `mc:remark*`, коды `G01/G01S/G02/DUP/OVL/V01/M01/M02/`
  `X01/OPN/SCL/GEN`, отчёт `<DWG> Отчёт.txt`, сводка в консоль.
- **Спецмарки `Дв/Ок/Вр`** — только заполнениям вне ячеек; `Ряд` очищается,
  `G01` снимается.
- **`mark:fill-clear-attrs-ename`** останавливается на `SEQEND`/не-`ATTRIB`.
- **Карта марок MarkV** `*mk:mark-map*` заполняется на этапах 2 и 3, чтобы
  MLINE-элементы попадали в ведомость с маркой, а не `—`.
- **М.п. в ведомости** считается от целой длины, напечатанной в таблице.
- **Совместная шкала**: сначала общий probe, при сбое — союз локальных probe,
  затем fallback по ригелям (`SCL`).
- **Компактная шкала**: резерв старых ширин Т-половин удалён.
- **Построчные Т-половины** печатаются только при `*mark:sec-diag*`.
- **Чистка**: удалены 19 разработческих команд, 66 неиспользуемых функций,
  дубли определений, внешние базы `MarkV-bases.lsp`, поиск исходников.

## 5. Шкалы

- MarkZ: фактические длины ригелей ∪ фактические ширины секций.
- MarkV: тот же список через probe.
- 2245 не резервируется; 2250 на большом чертеже = 18, `Рг18`.
- В раздельном режиме — локальные шкалы по витражам.

## 6. Отчёты и журналы

- `MARKZ_LOG.txt`, `MARKV_LOG.txt` — дозапись.
- `<DWG> Отчёт.txt` — статистика, коды, замечания.
- `<DWG> Шкала.txt` — совместная или по витражам.
- XLS — две ведомости.
- Отчётных таблиц AutoCAD нет.

## 9. Известные ограничения

- `V01 3` в совместном режиме — 6 кластеров, не дефект.
- `OPN` — неполное покрытие ячейки проёмом.
- `Артикул = —` у MLINE.
- `Сэндвич/Стемалит = 0` в `МАРКАВСЕ`.
- Старые выноски на слое `Маркировка` не удаляются.
- Журналы в дозапись.
- Raw GitHub отдаёт UTF-8; используйте `dist/MARK.lsp.zip`.
