# MERGE.md — история слияния и текущее устройство

**Статус:** `MARK.lsp` — единственный источник истины. MarkZ `48.49/36.8`,
MarkV `7.1/33.20`, ядро `1.0`. Версия одного файла — `1.1`.

## 1. Зачем один файл

Раньше требовалось загружать `MARKCORE.lsp`, `MARKZ.lsp`, `MarkV.lsp` в
правильном порядке. Теперь — один `MARK.lsp`:

- одно `(load ...)`;
- одна команда полного цикла `МАРКАВСЕ`;
- один `U` на весь цикл;
- нет внешних баз и поиска исходников;
- меньше команд и мёртвого кода.

## 2. Текущая структура

```text
MARK.lsp        единственный рабочий файл и источник истины
backup/         исторический архив 48.48 (не собирается, не загружается)
tests/          9 активных продуктовых тестов
legacy/
  tests/        исторические тесты 48.38–48.50
  tools/        старый build_single.py
docs/           MERGE.md, CHANGELOG.md, legacy/
acceptance/     протоколы приёмки
dist/           MARK.lsp.zip (CP1251)
```

`MARK.lsp` правится напрямую. Сборщик выведен из процесса: он остался только
в `legacy/tools/` как история того, как был получен первый единый файл.
Откат к сборке из трёх исходников — через тег/исторические коммиты, не через
текущий `main`.

## 3. Как был получен единый файл

Исторически `MARK.lsp` собирался из `HEADER + REGISTRY + MARKCORE + MARKZ +
MarkV + TAIL`. Сборщик:

1. вырезал загрузчики ядра и финальные баннеры модулей;
2. переименовывал `c:МАРКАВ` в `mk:a-all`, оставляя тонкую обёртку;
3. добавлял ключевое слово источника в `mark:a-all`;
4. добавлял цикл `МАРКАВСЕ`/`MARKALL`;
5. применял производственные патчи;
6. вырезал разработческие команды и мёртвые функции;
7. проверял CP1251/CRLF, BOM/U+FFFD, `fboundp`, внешние загрузки.

Этот этап завершён. Дальше `MARK.lsp` — обычный исходный файл.

## 4. Что вошло в единый файл

- Реестр замечаний `mc:remark*`, коды `G01/G01S/G02/DUP/OVL/V01/M01/M02/`
  `X01/OPN/SCL/GEN`, отчёт `<DWG> Отчёт.txt`, сводка в консоль.
- Спецмарки `Дв/Ок/Вр` — только заполнениям вне ячеек; `Ряд` очищается,
  `G01` снимается.
- `mark:fill-clear-attrs-ename` останавливается на `SEQEND`/не-`ATTRIB`.
- Карта марок MarkV `*mk:mark-map*` заполняется на этапах 2 и 3, чтобы
  MLINE-элементы попадали в ведомость с маркой, а не `—`.
- М.п. в ведомости считается от целой длины, напечатанной в таблице.
- Совместная шкала: общий probe → союз локальных → fallback по ригелям
  (`SCL`).
- Компактная шкала: резерв старых ширин Т-половин удалён.
- Построчные Т-половины печатаются только при `*mark:sec-diag*`.
- Удалены 19 разработческих команд, 66 неиспользуемых функций, дубли
  определений, внешние базы `MarkV-bases.lsp`, поиск исходников.

## 6. Шкалы

- MarkZ: фактические длины ригелей ∪ фактические ширины секций.
- MarkV: тот же список через probe.
- 2245 не резервируется; 2250 на большом чертеже = 18, `Рг18`.
- В раздельном режиме — локальные шкалы по витражам.

## 10. Известные ограничения

- `V01 3` в совместном режиме — 6 кластеров, не дефект.
- `OPN` — неполное покрытие ячейки проёмом.
- `Артикул = —` у MLINE.
- `Сэндвич/Стемалит = 0` в `МАРКАВСЕ`.
- Старые выноски на слое `Маркировка` не удаляются.
- Журналы в дозапись.
- Raw GitHub отдаёт UTF-8; используйте `dist/MARK.lsp.zip`.
