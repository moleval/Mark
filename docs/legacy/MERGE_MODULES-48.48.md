# Слияние MARKZ + MarkV в один модуль — пошаговая инструкция

Дата: 2026-11-06. Относится к состоянию ветки `arena/13d4d469-markz`:
MarkZ `48.48 / 36.7`, MarkV `7.0 / 33.19`, ядро `MARKCORE.lsp 1.0`.

---

## 0. Что считать «одним модулем»

Есть три разных вещи, которые обычно называют «слиянием»:

| Вариант | Что получается | Риск | Рекомендация |
|---|---|---|---|
| **A. Один загрузочный файл** из трёх исходников | `MARK.lsp` ≈ 16 400 строк: ядро + MarkZ + MarkV. Грузится одной командой, исходники и тесты остаются как есть | низкий | **делать первым** |
| **B. Единая команда полного цикла** | `МАРКАВСЁ`: сетка → каркас → марки → рядовка → ведомости, один UNDO, один протокол | средний | **делать вторым** |
| **C. Физическое слияние исходников** в один файл `MARK.lsp` | один файл-источник, три прежних удалены | высокий: ломаются все 15 offline-тестов, они читают `MARKZ.lsp` и `MarkV.lsp` | не делать |

Итог: **A + B**. Исходники остаются раздельными (это же и есть «единое ядро +
два модуля»), а пользователь получает один файл и одну команду.

## 1. Факты, на которых строится план

| Показатель | MARKZ.lsp | MarkV.lsp | MARKCORE.lsp |
|---|---:|---:|---:|
| Строк | 9 666 | 6 170 | 576 |
| `defun` | 425 | 323 | 50 |
| Команд AutoCAD (`c:*`) | 22 | 16 | 0 |
| Префикс функций | `mark:` | `mk:` | `mc:` |
| Глобальные переменные | `*mark:*`, `*mtab:*` | `*mk:*` | `*mc:*` |
| Журнал | `MARKZ_LOG.txt` | `MARKV_LOG.txt` | — |
| Ядро | грузит через `mark:core-ensure` | грузит через `mk:core-ensure` | — |

Проверено по коду:

- **нет ни одного общего `defun`** между MarkZ и MarkV (0 пересечений);
- **нет ни одной общей команды** (0 пересечений), значит 38 команд после сборки
  сохраняются без переименований;
- общий объём сборки ≈ 16 400 строк / 679 КБ — для `load` это нормальные
  секунды, ограничение AutoLISP далеко;
- обе программы на верхнем уровне выполняют одно и то же: `(vl-load-com)`,
  загрузку ядра, `setq` глобальных настроек и печать баннера с таблицей команд.
  Именно это и надо склеить в одном экземпляре.

## 2. Целевая структура собранного файла

```text
MARK.lsp
├── шапка сборки: что внутри, версии, как собрано
├── (vl-load-com)                       один раз
├── MARKCORE.lsp                        целиком, без завершающего флага
├── MARKZ.lsp                           без (vl-load-com), без загрузчика ядра,
│                                       без финального баннера
├── MarkV.lsp                           без (vl-load-com), без загрузчика ядра,
│                                       без финального баннера
├── (setq *mc:core-ready* t)            флаг ядра — после всех определений
├── (mark:reset-state)                  уже есть в MarkZ, вызывается один раз
├── объединённый баннер + таблица команд
└── (princ)
```

Порядок важен: ядро обязано идти **до** первых исполняемых форм модулей
(`mark:reset-state`, `mk:register-base`, баннеры), потому что они уже вызывают
`mc:*`.

---

## 3. Правила склейки

| Что | Действие |
|---|---|
| `(vl-load-com)` | оставить **один**, в начале сборки |
| `(setq *mc:core-file* …)` и `(defun mark:core-ensure …)` / `(mk:core-ensure …)` | **вырезать**: ядро уже внутри файла |
| `(setq *mc:core-ready* nil)` в начале ядра | оставить |
| `(setq *mc:core-ready* t)` в конце ядра | **вырезать** и поставить один раз после MarkV |
| финальные баннеры обоих модулей (`mark:help-*`, `mk:help-*`) | **вырезать**, заменить одной общей таблицей |
| `(mark:reset-state)` | оставить на своём месте (после определений MarkZ) |
| `(mk:register-base "СИАЛ" …)` | оставить: это инициализация баз профилей |
| `*error*`, `UndoMark` | не трогать при склейке; объединять только в этапе B |
| префиксы `mark:` / `mk:` / `mc:` | **не переименовывать**: в этом весь смысл — обёртки и вызовы уже разведены |

## 4. Этап 1 — маркеры в исходниках

Чтобы сборщик не искал строки «на глаз», в три файла добавляются комментарии-
маркеры. Они ничего не делают и переживают любые правки.

В `MARKCORE.lsp`, вокруг последних строк:

```lisp
;;;>>> BUILD:CUT-START core-tail
(setq *mc:core-ready* t)

(princ)
;;;>>> BUILD:CUT-END core-tail
```

В `MARKZ.lsp` (MarkV — аналогично, со своими именами):

```lisp
;;;>>> BUILD:CUT-START head
(vl-load-com)
... блок «ЕДИНОЕ ЯДРО» ...
(mark:core-ensure)
;;;>>> BUILD:CUT-END head
```

```lisp
;;;>>> BUILD:CUT-START tail
(mark:help-border)
... таблица команд MarkZ ...
(princ)
;;;>>> BUILD:CUT-END tail
```

Проверка: `python3 tests/lisp_structure.py` остаётся `OK` (комментарии не влияют).

## 5. Этап 2 — сборщик `tools/build_single.py`

Скрипт детерминированный: одинаковый вход → одинаковый байт-в-байт выход.
Кладётся в `tools/`, запускается вручную и в тестах.

```python
# -*- coding: utf-8 -*-
"""Сборка одного загрузочного файла MARK.lsp из MARKCORE + MARKZ + MarkV."""
from pathlib import Path
import sys

ROOT = Path(__file__).resolve().parents[1]
OUT = ROOT / "MARK.lsp"
FILES = ["MARKCORE.lsp", "MARKZ.lsp", "MarkV.lsp"]


def read(name):
    return (ROOT / name).read_bytes().decode("cp1251").replace("\r\n", "\n")


def cut_block(text, tag, name):
    """Вырезать блок между маркерами BUILD:CUT-START/END."""
    start = f";;;>>> BUILD:CUT-START {tag}"
    end = f";;;>>> BUILD:CUT-END {tag}"
    i = text.index(start)
    j = text.index(end, i) + len(end)
    return text[:i] + text[j:]


def require(cond, msg):
    if not cond:
        raise SystemExit("СБОРКА ОСТАНОВЛЕНА: " + msg)


core = cut_block(read("MARKCORE.lsp"), "core-tail", "MARKCORE")
markz = read("MARKZ.lsp")
markv = read("MarkV.lsp")
markz = cut_block(cut_block(markz, "head", "MARKZ"), "tail", "MARKZ")
markv = cut_block(cut_block(markv, "head", "MarkV"), "tail", "MarkV")

HEADER = """;;;=====================================================================
;;;  MARK.lsp — ЕДИНАЯ СБОРКА MarkZ + MarkV
;;;  Состав: MARKCORE.lsp (ядро), MARKZ.lsp (заполнения), MarkV.lsp (каркас)
;;;  Собрано tools/build_single.py; править исходники, а не этот файл.
;;;=====================================================================
"""

TAIL = """
;;;=====================================================================
;;;  СБОРКА: ядро и оба модуля загружены
;;;=====================================================================
(setq *mc:core-ready* t)

(mark:emit (strcat "\\n[MARK] Сборка MARKCORE " (mc:core-version)
                   " + MarkZ " *mark:rev* " / " *mark:build*
                   " + MarkV " *mk:ver* " / " *mk:build*))
(mark:help-border)
(mark:help-header)
(mark:help-row "МАРКАВСЁ (MARKALL)" "Полный цикл: сетка -> каркас -> марки -> рядовка -> ведомости")
(mark:help-row "МАРКАЗ / МАРКАР / МАРКАТАБЛ" "Заполнения: марки, рядовка, ведомость")
(mark:help-row "МАРКАВ / МАРКАВТАБЛ" "Каркас: стойки, ригели, ведомость профилей")
(mark:help-border)
(princ)
"""

text = HEADER + core + markz + markv + TAIL
raw = text.replace("\r\n", "\n").replace("\n", "\r\n").encode("cp1251")

# --- самопроверки сборки -------------------------------------------------
require(b"\xef\xbb\xbf" not in raw, "BOM в начале файла")
require(b"(fboundp" not in raw, "fboundp в сборке")
require(raw.count(b"(vl-load-com)") == 1, "(vl-load-com) должен быть один")
require(b"(mark:core-ensure)" not in raw and b"(mk:core-ensure)" not in raw,
        "загрузчик ядра остался в сборке")

if "--check" in sys.argv:
    current = OUT.read_bytes() if OUT.exists() else b""
    if current != raw:
        raise SystemExit("MARK.lsp устарел: пересоберите tools/build_single.py")
    print("MARK.lsp актуален")
else:
    OUT.write_bytes(raw)
    print(f"MARK.lsp: {raw.count(b'\\n')} строк, {len(raw)} байт")
```

Запуск:

```bash
python3 tools/build_single.py          # пересобрать
python3 tools/build_single.py --check  # проверить, что закоммиченный файл свежий
```

## 6. Этап 3 — подготовка к единой команде

Сейчас у MarkZ есть функция пакета `mark:a-all`, а у MarkV пакет целиком живёт
**внутри команды** `c:МАРКАВ` (строка ≈ 5508). Командой из команд нельзя
пользоваться, поэтому сначала:

1. Тело `c:МАРКАВ` переносится в `(defun mk:a-all (...))` **без изменений**;
2. `(defun c:МАРКАВ () (mk:a-all))` — тонкая обёртка;
3. Выборка передаётся, а не запрашивается повторно: MarkZ уже умеет это через
   `*mark:reuse-sel*` и `*mark:fills*`, у MarkV есть `*mk:last-ss*` — пакет
   должен использовать их, если они заполнены.

Проверка после шага: `МАРКАВ` работает как раньше (тот же журнал, та же
ведомость), `tests/lisp_structure.py` — `OK`, команда на месте.

## 7. Этап 4 — команда `МАРКАВСЁ` / `MARKALL`

Скелет (имена функций сверить с фактическим кодом на момент работы):

```lisp
(defun mark:all-cycle (/ kw ss doc was-reuse)
  (mark:log-start)                         ; один журнал на весь цикл
  (mark:out "========================================")
  (mark:out " МАРКАВСЁ — полный цикл")
  (mark:out "========================================")

  ;; один выбор области на весь цикл
  (setq ss (ssget))
  (if (null ss) (progn (mark:out "[INFO] Выбор отменён.") (exit)))

  (setq doc (mark:ax-get (vlax-get-acad-object) "ActiveDocument"))
  (if (not (mark:ax-invoke-ok doc "StartUndoMark" nil))
    (mark:out "[WARN] UNDO-группа не открыта."))

  (setq was-reuse *mark:reuse-sel*)
  (unwind-protect
    (progn
      ;; 1. сетка заполнений: выбор уже есть
      (setq *mark:reuse-sel* nil)
      (mark:fill-main)                     ; режим «Сетка»
      (setq *mark:reuse-sel* t)            ; 2-4 этапы работают по готовым блокам

      ;; 2. каркас: MarkV по тем же объектам
      (setq *mk:last-ss* ss)
      (mk:a-all)

      ;; 3. заполнения: марки, рядовка, ведомость
      (mark:a-all-kw "Заполнения")
      (mark:ar-main)
      (mtab:main))

    ;; UNDO закрывается всегда
    (progn
      (setq *mark:reuse-sel* was-reuse)
      (mark:ax-invoke-ok doc "EndUndoMark" nil)))

  (mark:out "[OK] Полный цикл завершён.")
  (princ))

(defun c:МАРКАВСЁ () (mark:all-cycle))
(defun c:MARKALL  () (mark:all-cycle))
```

Ключевые требования к команде:

- **один UNDO** на весь цикл (`StartUndoMark` / `EndUndoMark` в `unwind-protect`);
- **один выбор** области: сетка и каркас работают по одному и тому же набору,
  иначе шкалы разойдутся;
- **порядок неизменен**: сетка → каркас (MarkV) → заполнения. Именно в этом
  порядке MarkV получает шкалу MarkZ через read-only probe и не уходит в
  fallback;
- **ошибка на любом этапе** печатает `[ERROR]` и прекращает цикл, но закрывает
  UNDO-группу и восстанавливает `*mark:reuse-sel*`.

Для этого в MarkZ понадобится вариант `mark:a-all` без интерактивного вопроса
об источнике (в скелете — `mark:a-all-kw "Заполнения"`): вынести тело в
функцию с ключевым словом, а `c:МАРКАЗАП` оставить обёрткой с `getkword`.

## 9. Этап 6 — тесты

Добавляется `tests/bundle_48_50.py`, который проверяет **сборку**, а не логику:

```python
# -*- coding: utf-8 -*-
"""MARK.lsp: сборка полная, свежая и без дублей."""
from pathlib import Path
import re, subprocess, sys

ROOT = Path(__file__).resolve().parents[1]
sys.path.insert(0, str(ROOT / "tests"))
from lisp_structure import parse

raw = (ROOT / "MARK.lsp").read_bytes()
text = raw.decode("cp1251")

assert not raw.startswith(b"\xef\xbb\xbf")
assert raw.count(b"\n") == raw.count(b"\r\n")
parse(text)                                  # формы закрыты

def names(t):
    return re.findall(r"\(defun\s+([^\s()]+)", t)

bundle = names(text)
dups = {n for n in bundle if bundle.count(n) > 1}
assert not dups, dups

for part in ("MARKCORE.lsp", "MARKZ.lsp", "MarkV.lsp"):
    for n in names((ROOT / part).read_bytes().decode("cp1251")):
        if part == "MARKCORE.lsp":
            assert n in bundle, f"{n} потерян при сборке"
        else:
            assert n in bundle, f"{n} потерян при сборке"

for cmd in ("c:МАРКАЗАП", "c:МАРКАР", "c:МАРКАТАБЛ", "c:МАРКАЗАЛ",
            "c:МАРКАВ", "c:МАРКАВТАБЛ", "c:МАРКАВСЁ", "c:MARKALL"):
    assert "(" + cmd + " " in text or "(" + cmd + ")" in text, cmd

assert text.count("(vl-load-com)") == 1
assert "(mark:core-ensure)" not in text and "(mk:core-ensure)" not in text
subprocess.run([sys.executable, str(ROOT / "tools" / "build_single.py"), "--check"],
               check=True, capture_output=True)
print(f"OK: сборка {len(bundle)} функций, команды на месте, файл свежий")
```

В `tests/lisp_structure.py` добавляется `MARK.lsp` в список по умолчанию.
Остальные 15 тестов **не трогаются** — они по-прежнему читают исходники.

## 12. Откат

Всё обратимо:

- пользователь просто грузит `MARKCORE.lsp` + `MARKZ.lsp` + `MarkV.lsp` — как
  сейчас;
- `MARK.lsp` удаляется, исходники не тронуты;
- если что-то пошло не так в этапе B, `c:МАРКАВСЁ` убирается, `mk:a-all`
  остаётся полезным сам по себе (это чистое выделение тела команды).

Никаких необратимых шагов в плане нет: `MARK.lsp` — генерируемый файл.

## 13. Риски и как их снимать

| Риск | Как снимается |
|---|---|
| Сборка «съест» чужой `(vl-load-com)` или загрузчик ядра | самопроверки в сборщике: ровно один `(vl-load-com)`, ни одного `core-ensure` |
| Разъедется с исходниками | `build_single.py --check` в тестах |
| Разный порядок инициализации | ядро первым, `*mc:core-ready* t` — последним; проверка загрузки в AutoCAD |
| Двойной UNDO в цикле | `StartUndoMark`/`EndUndoMark` только в `mark:all-cycle`, модули не открывают свою группу, когда `*mark:reuse-sel*` включён |
| Расхождение шкал из-за двух выборок | один `ssget` на цикл, `*mk:last-ss*` и `*mark:reuse-sel*` передаются явно |
| Дубли `defun` после будущих правок | тест на дубликаты имён в сборке |
| Объём файла | 679 КБ — не проблема; при желании вынести проверки в отдельный файл |

их лучше делать после вашего контрольного прогона `MARK.lsp` из этапа 2.
