# MARKZ + MarkV — маркировка витражей (заполнения и каркас)

**Репозиторий:** https://github.com/moleval/MarkZ — **единственный источник правды.**
**Модуль заполнений:** [`MARKZ.lsp`](MARKZ.lsp) — Ред. `48.36` / Ред. `36.3`
**Модуль каркаса:** [`MarkV.lsp`](MarkV.lsp) — Ред. `7.0` · Ред. `33.12` (ранее `MarkZV.lsp`)
**Кодировка:** в рабочем дереве CP1251 + CRLF, в Git — UTF-8 через `.gitattributes`

Два самостоятельных модуля AutoLISP, которые работают по одной шкале размеров:

| Модуль | Что маркирует | Команды |
|---|---|---|
| `MARKZ.lsp` | **заполнения**: секции, ярусы, подъячейки, подындексы; рядовка; ведомость заполнений | `МАРКАЗАП`, `МАРКАРОВКАЗАП`, `МАРКАЗАПРЯД`, `МАРКАЗАПТАБЛ`, `МАРКАЗАПБЛОК` |
| `MarkV.lsp` | **каркас**: стойки и ригели, артикулы профилей, ведомость профилей и закладных | `МАРКАВ`, `МАРКАВГЕОМЕТРИЯ`, `МАРКАВСТ`, `МАРКАВРГ`, `МАРКАВТАБЛ` |

Схема версий у обоих модулей одна: **`Ред. N.N`** (крупные задачи) + **`Ред. M.N`** (итерация правок).
Слова «build» в логах и документах нет — только две записи «Ред. N.N».
Значения — в `*mark:rev*` / `*mark:build*` (MarkZ) и `*mk:ver*` / `*mk:build*` (MarkV).

## Установка

```lisp
(load "D:/MARKZ.lsp")     ; заполнения
(load "D:/MarkV.lsp")     ; каркас (стойки и ригели)
```

В консоли обе печатают баннер вида `Загружен Ред. N.N / Ред. M.N` и таблицу команд.
Проверка синтаксиса — штатная, из AutoExtraction (`CHKALL` / `CHKFILE` / `CHKLOAD`);
модульные проверки — `TEST 00` при загрузке MarkZ и `МАРКАВСКОБКИ` в MarkV.

> **Где разработка.** Ветка по умолчанию `main` обновляется только слиянием готовой
> редакции. Текущая работа ведётся в ветках `arena/*`; состав актуальной ветки описан
> в `AGENTS.md`, раздел «Где что лежит».

## Синхронизация номеров MarkZ ↔ MarkV

Одна и та же цифра марки означает один размер «в свету» в обеих программах:
секция 1430 в MarkZ и ригель 1430 в MarkV получают **одинаковый номер**.
Правила и протокол сверки — [`SYNC_MARKZV.md`](SYNC_MARKZV.md); распределение ролей:

| Программа | Ответственность |
|---|---|
| **MarkV** | стойки и ригели; источник длин; таблица профилей и закладных |
| **MarkZ** | заполнения: секции, ярусы, подъячейки, подындексы; рядовка; ведомость заполнений |

## Проверка синтаксиса

Основная программа **AutoExtraction** уже содержит проверку модулей:
`CHKFILE` — один файл, `CHKALL` — все загруженные модули и плагины,
`CHKLOAD` — поиск места сбоя загрузки. Пользуйтесь ими как основным инструментом.

Свои проверки в модулях остаются как страховка, если AutoExtraction не загружен:

| Модуль | Что делает |
|---|---|
| `MARKZ.lsp` | `TEST 00` при загрузке — печатает `Прогон скобок — OK` и число скобок |
| `MarkV.lsp` | `МАРКАВСКОБКИ` — если AutoExtraction загружен, вызывает его `CHKALL` (все модули и плагины); иначе работает встроенный сканер по `MarkV.lsp` |

Достаточно одной проверки: `CHKALL` покрывает все модули сразу и ищет не только
скобки, но и место сбоя загрузки (`CHKLOAD`). Встроенные проверки модулей нужны
только для случая, когда AutoExtraction не загружен.

## Команды MARKZ.lsp (заполнения)

```text
МАРКАЗАП → Режим / источник → выбор объектов
```

| Команда | Что делает |
|---|---|
| **МАРКАЗАП** (`MARKZ`) | Полный цикл: раскладка заполнений по ячейкам каркаса (или по готовым блокам) → марки → рядовка → ведомость, **один UNDO** |
| **МАРКАРОВКАЗАП** (`MARKAR`) | Только маркировка («Марка») уже существующих блоков «Заполнение в витраж» |
| **МАРКАЗАПРЯД** (`MARKAR`) | Только рядовка: блоки «Ряд заполнений» (номера снизу, буквы справа) |
| **МАРКАЗАПТАБЛ** (`MARKTABLE`) | Только ведомость: таблица AutoCAD + XLS (CSV — тихий фолбэк) |
| **МАРКАЗАПБЛОК** (`MARKFILL`) | Только раскладка блоков «Заполнение в витраж» по ячейкам; атрибуты пустые |
| **МАРКАЗАПГЕО** | `[DIAG]` геометрии секций: вертикали, импосты, горизонтали |
| **МАРКАЗАПТЕСТ** | Проверка ячейки на тестовом блоке из линий |
| **МАРКАЗАПКОПИИ** | Полные дубли объектов — в группу и подсветка (без удаления) |
| **МАРКАДИАГ** | Диагностика: что за блок стоит у окна/двери и как его видит LISP |
| **Сетка-мультилинии** / **Точка-мультилинии** / **Сетка-динамика** / **Точка-динамика** / **Полилинии** | Принудительный режим раскладки без подменю |

### Режимы раскладки — МАРКАЗАПБЛОК

```text
МАРКАЗАПБЛОК → Режим [Сетка/Точка/Полилиния] <Сетка> → выбор объектов
```

| Режим | По умолчанию / Ключи | Как работает |
|-------|----------------------|--------------|
| **Сетка** | **Enter**, `1` | Выбор элементов витража (MLINE, LINE, ARC) → автоматическое определение границ, фильтрация открытых проёмов, объединение Т-образных стыков стоек/ригелей и расчёт всех ячеек |
| **Точка** | `2` | Указание точки внутри замкнутого контура ячейки (поиск границ в окне 5000 мм) |
| **Полилиния** | `П` | Указание готовых замкнутых полилиний границ ячеек |

- **Особенности геометрии и вставки:**
  - Вставка в **левый нижний** угол ячейки (rot 0).
  - Свойства `Ширина в свету` и `Высота в свету` равны точным габаритам светового проёма ячейки.
  - Поддержка **MLINE** (мультилиний) со стойками/ригелями: центральные оси вычисляются через AABB, узлы округляются до 1 мм.
  - **Т-образные примыкания (T-junctions):** если промежуточная стойка подходит снизу к ригелю и не продолжается вверх, ячейки над ригелем автоматически объединяются в единый сквозной проём (например, фрамуга).
  - **Контроль наклона стоек:** строгий допуск `*mark:fill-slope* = 0.0033` (не более 10 мм на 3000 мм высоты) исключает ложные срабатывания.
  - **Очистка атрибутов:** атрибуты нового блока гарантированно обнуляются после установки размеров (чтобы исключить дефолтные значения динамического блока).

### Пакет МАРКАЗАП: что происходит по шагам

```text
МАРКАЗАП
  1. Режим каркаса: 1/2 мультилинии, 3/4 динамика, 5/6 все-типы, П — полилинии
  2. Раскладка блоков «Заполнение в витраж» по ячейкам      (МАРКАЗАПБЛОК)
  3. Маркировка: буква+номер по размерам + суффиксы          (МАРКАРОВКАЗАП)
  4. Рядовка условных обозначений                            (МАРКАЗАПРЯД)
  5. Ведомость: таблица / XLS                                (МАРКАЗАПТАБЛ)
```

Всё выполняется в одной транзакции UNDO: откат одной командой `_U`.
Если каркас уже промаркирован, шаг 2 можно пропустить — источники
`Заполнения` и `Смешанный` работают по готовым блокам.

## Формула марки (MarkZ)

```text
[Витраж] + БУКВА(по ширине) + НОМЕР(по высоте) + суффикс
```

Примеры: `ВН-5 А1`, `ВН-5 Б3стм`, `В-7 В2снд`

| Visibility | Суффикс |
|------------|---------|
| Стемалит | `стм` |
| Сэндвич | `снд` |

Алфавит без **Й** и **З**. Одинаковый размер (допуск 0.5 мм) → один базис «буква+номер».

---

## Рядовка (кратко)

- Индекс `Ряд` = **от размера W/H** (та же логика, что МАРКАЗ), не от строки марки.
- Основной ряд — сплошной; наложения — на линиях ниже/правее с шагом **150 мм**, по убыванию длины.
- Dynamic-размер блока: **L/2 + 25** мм.
- Горизонталь — поворот **270°**, вертикаль — **0°**.
- Группы: `Рядовка горизонтальная`, `Рядовка вертикальная`.

---

## Ведомость (кратко)

- Заголовок **«Заполнение»**
- `№ | Тип | Марка | Высота, мм | Ширина, мм | Кол-во, шт. | Площадь, м2`
- Припуск размеров в таблице: **+26 мм**
- XLS с формулами; CSV только если XLS не создался (в меню CSV нет)

---

## Самодиагностика

При каждой МАРКАЗ: **TEST 00–14** + **[DIAG]** по базисам stem/сэнд.

- `TEST 00` — баланс скобок исходника (падает сразу при повреждении файла).
- `TEST 14` — PRE-CHECK; запись только после OK.
- `[DIAG] КОНФЛИКТОВ: N` — у заполнений одного типоразмера разные базисы (сверить W/H в свойствах).

## MarkV.lsp — каркас: стойки и ригели, по витражам

```lisp
(load "D:/MarkV.lsp")
```

Команды: `МАРКАВ` (пакет), `МАРКАВГЕОМЕТРИЯ`, `МАРКАВСТ`, `МАРКАВРГ`, `МАРКАВТАБЛ`,
`МАРКАВДИАГНОЗ`, `МАРКАВБАЗЫ`, `МАРКАВСКОБКИ`.

### Многовитражный конвейер (Ред. 7.0)

Раньше на всю выборку брался один блок «Атрибуты витража», и все объекты получали
его префикс — при нескольких витражах это давало один префикс на всех (например `ВН-7`).
Теперь так:

```text
МАРКАВ
  1. Выборка: выбраны объекты — работаем по ним; Enter — весь чертёж
  2. Рамки ищутся по ВСЕМУ чертежу (даже если в выборку не попали)
  3. Принадлежность: BBOX объекта × CaptureBBox рамки — максимальная площадь
     нет пересечения → <ВНЕ РАМОК>, объект не маркируется
  4. Группы по атрибуту «Витраж» рамки
  5. По каждой группе отдельно: сбор → Т-стыки → топология → стойки → ригели
  6. Общая ведомость по всем витражам (таблица + один XLS)
```

- CaptureBBox учитывает динамические `Ширина/Высота рамки`, `Вертикаль`, `Горизонталь`
  (все четыре состояния отражения), масштаб и поворот.
- Внутри витража свои шкалы: `ВН-1 Ст1` и `ВН-2 Ст1` — независимые номера;
  шкала длин ригелей (`Рг1…РгN`) строится внутри витража.
- Модель 2D и выноски — свои группы: `Сетка_витража_<витраж>`, `Маркировка_<витраж>`.
- Рамка без атрибута «Витраж» получает имя `ВИТРАЖ-N` (порядок слева-направо, сверху-вниз).
- Ведомость одна на прогон, имя файла: `<чертёж> Стойки ригели витража <N витражей>.xls`.
- **Раскладка таблиц.** Ведомость идёт столбиком от указанной точки (куски по
  50 строк, раздел витража не разрывается). Таблица закладных («пятки») и
  таблица условных обозначений ставятся **справа от ведомости**, одна под
  другой — вертикальная колонка на всю высоту листа, поэтому они больше не
  наезжают на ведомость. В логе печатается «Закладные и обозначения: справа
  от ведомости, X=… Y=…».
- **Точка вставки ведомости спрашивается.** После уборки сеток `МАРКАВ`
  печатает «Точка вставки ведомости <Enter — X=… Y=…>»: щёлчок — таблица
  встанет в указанное место, Enter — в автоматическое (под самым нижним
  витражом, по левому краю). Отключить вопрос: `(setq *mk:ask-table-pt* nil)`.
- **Таблицы строятся мгновенно** (метод `FAST_TABLES.md`): одна вставка сразу
  конечного размера, пересборка подавлена на всё заполнение, снимается один раз
  в конце. Ведомость на 160 позиций появляется за доли секунды. Длинная
  ведомость режется на таблицы по 50 строк (раздел витража не разрывается),
  шапка повторяется, нумерация и «Итого» — сквозные; в логе печатается число
  таблиц и время: `[OK] Ведомость в чертеже: таблиц 3, позиций 160, …, время 0.xx с`.
- **Перекрытия** считаются только между заполнениями и между проёмами.
  Пара «заполнение + окно/дверь» — это один световой проём с двумя блоками
  (проём ставится поверх заполнений и часто занимает несколько ячеек), поэтому
  она не проверяется по габаритам и в ошибки не попадает.
- **Сетка моделей удаляется всегда** (если на вопрос «Оставить сетки витражей?»
  ответили «Нет»): одним проходом по слою `Сетка витража` и по именам групп
  `Сетка_витража_<витраж>`, после любого исхода первых трёх этапов. Сбой этапа
  не мешает уборке и построению ведомости.
- **Сбой одного витража не роняет прогон.** Каждый витраж обрабатывается в
  `mk:process-group` через `vl-catch-all-apply`; при ошибке печатается
  `[ERROR] Витраж <имя>: сбой обработки — <текст>`, прогон идёт дальше,
  в конце — сводка `[WARN] Сбоев в прогоне: N из M`. Причина почти всегда —
  нетиповой блок или потерянный атрибут, поэтому перед прогоном по новому
  чертежу полезен `МАРКАВДИАГНОЗ` (один блок) и `МАРКАВДИАГНОЗОПТОМ`
  (сводка по выборке: типы, стили, блоки, слои).
- **Окна и двери ищутся по маскам имён блоков**, а не по одному шаблону:
  `*mk:window-masks*` = `*ОКН*`, `*mk:door-masks*` = `*ДВЕР*`, плюс основные
  имена `*mk:block-window*` = `Окно КПТ60` и `*mk:block-door*` = `Дверной блок*`.
  Корни масок те же, что у проёмов в MarkZ (`*mark:opening-masks*`), чтобы
  «окно»/«дверь» в обоих модулях означали одно и то же. Створки (`*СТВОР*`)
  сознательно не включены — иначе они попадут в окна и изменят уже сверенные
  счётчики по витражам. Маски-исключения `*mk:opening-skip-masks*` = `*КАССЕТ*`:
  глухое заполнение, случайно совпавшее с `*ОКН*`, окном не становится.
  Своё семейство дописывается одной строкой в чертеже, код не правится:
  ```lisp
  (setq *mk:window-masks* (append *mk:window-masks* (list "*СТВОР*")))
  (setq *mk:door-masks*   (append *mk:door-masks*   (list "*ДВЕРНОЙ*")))
  ```
- **Нераспознанные вставки не теряются молча.** После разбивки по витражам
  печатается `[INFO] Вставок вне типов MarkV: N` и до десяти имён блоков с
  количеством (`имя x число`); полный список — в разделе
  «НЕ РАСПОЗНАННЫЕ ВСТАВКИ» файла `MARKZV_MODEL.txt`. Если в этом списке
  оказалось семейство окон/дверей — это и есть причина «окна = 0» или
  «двери = 0»: имя блока дописывается в маску, код не меняется.

### Марки

- **Стойки:** `<Витраж> Ст<N>`; зеркальная пара — `Ст<N>.1 / Ст<N>.2`.
- **Ригели:** `<Витраж> Рг<N>…`, где `N` — номер длины в свету по шкале витража,
  далее суффиксы: `м`/`ср`/`б` (сечение), `ок`/`окх2`/`дв`, `тх`/`хт`, `+н`,
  `т` (вертикальный импост), `.1`/`.2`/`.3` (Т-соединения).
- Длина ригеля в раскрой = размер в свету + припуск системы (КП50 — 0, КП50К — +25 мм).

