# MARK.lsp — единая сборка MarkZ + MarkV

**Рабочий файл:** [`MARK.lsp`](MARK.lsp) — один загрузочный файл для AutoCAD.
**Версии:** MarkZ `Ред. 48.49 / Ред. 36.8`, MarkV `Ред. 7.1 / Ред. 33.20`,
ядро `Ред. 1.0`. Версия одного файла — `Ред. 1.4`.

`MARK.lsp` содержит ядро `mc:*`, заполнения (MarkZ), каркас (MarkV) и общий
цикл. Это **единственный источник истины**: файл правится напрямую.
`MARKCORE.lsp`, `MARKZ.lsp`, `MarkV.lsp` — исторический архив в
[`backup/`](backup/), в сборке и загрузке не участвуют.

## Установка

```lisp
(load "D:/MARK.lsp")
```

После загрузки:

```text
Mark.lsp Ред. 1.4 — MarkZ Ред. 48.49 / Ред. 36.8 + MarkV Ред. 7.1 / Ред. 33.20
```

и таблица рабочих команд.

> **Кодировка:** файл — CP1251 + CRLF. Не пересохраняйте его в UTF-8.
> Скачивайте `dist/MARK.lsp.zip` или клонируйте репозиторий. Кнопка **Raw**
> на GitHub отдаёт UTF-8 и может сломать кириллические имена команд.

## Команды

| Команда | Алиас | Назначение |
|---|---|---|
| `МАРКАВСЕ` | `MARKALL` | полный цикл: заполнения + каркас + обе ведомости |
| `МАРКАЗАП` | `MARKA` | заполнения: раскладка → марки → рядовка → ведомость |
| `МАРКАЗАПБЛОК` | `MARKFILL` | только раскладка заполнений по сетке |
| `МАРКАРОВКАЗАП` | `MARKZ` | только маркировка заполнений |
| `МАРКАЗАПРЯД` | `MARKAR` | только рядовка заполнений |
| `МАРКАЗАПТАБЛ` | `MARKTABLE` | только ведомость заполнений |
| `МАРКАВ` | — | каркас: геометрия → стойки → ригели → ведомость профилей |
| `МАРКАВГЕОМЕТРИЯ` | — | этап 1 каркаса |
| `МАРКАВСТ` | — | этап 2: марки стоек |
| `МАРКАВРГ` | — | этап 3: марки ригелей |
| `МАРКАВТАБЛ` | — | этап 4: ведомость профилей, закладные, обозначения |
| `МАРКАВДИАГНОЗОПТОМ` | `MARKVBULKDIAG` | диагностика объектов каркаса |

Команды вводятся в командной строке **без скобок**. Из LISP-выражения нужен
префикс `c:`: `(c:МАРКАВСЕ)`.

## Как работать

### Полный цикл

```text
МАРКАВСЕ
```

1. Выбор объектов (Enter — весь чертёж).
2. MarkZ: раскладка заполнений, марки, рядовка, ведомость заполнений.
3. MarkV: геометрия, стойки, ригели, ведомость профилей.
4. Один `U` отменяет весь цикл.

`МАРКАВСЕ` всегда вставляет **новый** комплект заполнений. Если в чертеже уже
разложены заполнения с нужной видимостью (сэндвич/стемалит), используйте
`МАРКАВ`, затем `МАРКАЗАП` с источником «Заполнения».

### Только каркас

```text
МАРКАВ
```

Этапы 1–4 можно запускать отдельно: `МАРКАВГЕОМЕТРИЯ`, `МАРКАВСТ`,
`МАРКАВРГ`, `МАРКАВТАБЛ`.

### Только заполнения

```text
МАРКАЗАП
```

Источник: «Сетка» (по умолчанию) или «Заполнения» (уже стоящие блоки).
Этапы: `МАРКАЗАПБЛОК`, `МАРКАРОВКАЗАП`, `МАРКАЗАПРЯД`, `МАРКАЗАПТАБЛ`.

### Совместная и раздельная маркировка

При нескольких витражах MarkV и MarkZ спрашивают режим:

- **Совместная** — одна общая шкала размеров на все витражи; цифра марки
  заполнения и цифра `Рг` совпадают.
- **Раздельная** — у каждого витража своя шкала секций и строк; МаркV получает
  локальную шкалу через read-only probe.

## Маркировка: кратко

- Марка заполнения: `<Витраж> <Буква ряда><Номер секции>[.<подындекс>][суффикс]`.
  Пример: `ВН-1 И4`, `Вт-1 Х15.2`, `ВН-1 В4снд`.
- Номер — позиция **фактического** размера в шкале. Шкала строится только из
  реальных длин ригелей и реальных ширин секций.
- Старые ширины Т-половин **не резервируются**: в шкале только фактические
  размеры. Выровненная секция получает свой фактический номер — на контрольном
  большом чертеже `2250 = 18`.
- Подындекс `.1/.2` — часть расчленённой секции (по возрастанию ширины).
- Литеры `.а/.б` — разные высоты внутри одного яруса.
- Спецмарки `Дв`, `Ок`, `Вр` — только для заполнений вне ячеек; на блоках
  дверей, окон и вентрешёток они не ставятся.
- Стойки: `<Витраж> Ст<N>[.1/.2]`.
- Ригели: `<Витраж> Рг<N><т><.T-суффикс><профиль><примыкание>`.

Подробно — [`MARKUP_LOGIC.md`](MARKUP_LOGIC.md) и [`TZ.md`](TZ.md).

## Результаты прогона

В папке чертежа (`DWGPREFIX`):

| Файл | Что это |
|---|---|
| `MARKZ_LOG.txt` | протокол MarkZ |
| `MARKV_LOG.txt` | протокол MarkV |
| `<DWG> Отчёт.txt` | сводка прогона + список замечаний |
| `<DWG> Шкала.txt` | шкала секций (совместная или по витражам) |
| `<DWG> Заполнение Марки.xls` | ведомость заполнений |
| `<DWG> Стойки ригели витража ….xls` | ведомость профилей |
| `MARKZV_MODEL.txt`, `MARKZV_DIAG_ALL.txt` | дампы/диагностика |

Журналы пишутся **в дозапись**. В одном файле могут лежать несколько прогонов;
актуален последний блок. Отчёт содержит только текст и таблицу замечаний —
отчётных таблиц AutoCAD не создаёт (таблицы создаются только как ведомости).

## Известные ограничения

- `V01` — в совместном режиме 9 рамок могут группироваться в 6 геометрических
  кластеров; в кластере с двумя блоками «Атрибуты витража» берётся ближайший.
  Это не ошибка маркировки.
- `OPN` — проём не полностью покрывает ячейку; ячейка пропускается, узел нужно
  проверить вручную.
- `Артикул = —` у элементов из мультилиний: у MLINE нет атрибута «Артикул».
- `Сэндвич/Стемалит = 0` в `МАРКАВСЕ`: новые заполнения создаются с видимостью
  «Прозрачное 1».
- Старые выноски на слое `Маркировка` не удаляются автоматически; перед
  повторным прогоном их лучше убрать.

## Репозиторий

```text
MARK.lsp        — единственный рабочий файл и источник истины
backup/         — исторический архив исходников 48.48
tests/          — 12 активных продуктовых тестов
legacy/         — архив: старые исходники, тесты, сборщик
docs/           — MERGE.md, CHANGELOG.md, история
acceptance/     — протоколы приёмки
dist/           — MARK.lsp.zip для скачивания
```

`MARK.lsp` правится напрямую. Перед коммитом:

```bat
python tests\lisp_structure.py
python tests\bundle_48_50.py
python tests\production_48_55.py
```

Полный список активных тестов — [`tests/README.md`](tests/README.md).
Исторические тесты 48.38–48.50 — в [`legacy/tests/`](legacy/tests/), в
приёмку не входят.
